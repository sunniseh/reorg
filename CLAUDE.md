## What REORG is

A memecoin where the token is a job. Holding $REORG makes you an employee (no signup); an AI "boss" posts a daily task; code decides pass/fail; passers get paid in NEAR from a treasury; three straight misses means a 7-day layoff (tokens are never touched); an empty reserve for 3 days means bankruptcy and severance.

## Architecture (four components, spec §6)

1. **NEAR contract (Rust)** — source of truth for employees, tasks, results, salaries, treasury. Reads balance and total supply from the token via cross-contract calls (`submit` → `on_balance` callback).
2. **NEP-141 fungible token** — the memecoin itself.
3. **Boss service (server)** — holds the boss key and the daily secret; runs the scheduler (pick → generate → self-check solve → commit/open → close → finalize); serves personalized puzzles; calls boss-only contract methods.
4. **Tower game client (web, PixiJS/Phaser-style 2D)** — read-only renderer over contract views + event feed. It must never hold game logic. Characters derive from the wallet hash; the tower layout is computed from the employee list (tier, then balance) so every client renders the same tower.

## Invariants that span multiple components

- **Commit–reveal:** boss draws `day_secret`, calls `open_task` with `sha256(day_secret)`; the puzzle and expected answer for each wallet derive from `HMAC(day_secret, wallet)`; employees submit `hash(answer + wallet)`; `finalize_task` reveals the secret and the contract re-verifies every listed passer's answer hash. Boss service and contract must compute the HMAC/hash identically — change both together.
- **The LLM never decides anything.** It only writes flavor text (structured JSON: `task_text`, `announcements`, `tone_notes`, validated). Pass/fail, payouts and layoffs are code-only. If LLM output fails validation or the generated puzzle fails the solve-check (exactly one valid answer), fall back to a pre-written template.
- **Pay math:** weight = snapshotted balance × streak multiplier (`1 + 0.10 × streak`, cap 1.5); pay = tier bucket × weight / sum of weights in tier. Failed/skipped shares go to the reserve, not to other workers. Claim requires current balance ≥ 90% of snapshot (anti-dump), else forfeited to reserve.
- **"Day" means task number, not calendar date** (`last_pass_day`, streaks, layoff counters). Layoff status is computed lazily; the contract never loops over employees. Pass lists are capped per call and batched.
- **Epoch length is config** (24h prod, 3–5 min demo). Tier thresholds, bucket shares, income split, streak cap, layoff rules and anti-dump threshold are all contract config (spec §13) — never hardcode them.
- **Tasks must never involve money** and must be doable in ~60s from a phone.
- Demo-mode crowds must be clearly labeled simulated; the README must state which income paths are real vs simulated.

## Keeping the code portable

Isolate everything chain-specific (account/address types, token and treasury calls, wallet connect, tx signing, event ingestion) behind a thin adapter interface in each component. Keep game rules, puzzle generation, the HMAC/commit scheme, scheduler logic, and the renderer chain-agnostic, with no NEAR types leaking into them. Treat wallet identity as an opaque string.
